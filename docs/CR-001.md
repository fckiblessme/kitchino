# CR-001. Пороги решения о скидке — в файле конфигурации

| Поле | Значение |
|---|---|
| Идентификатор | CR-001 |
| Дата | 2026-11-23 |
| Затрагивает | `dishbatch/decision` — модуль-кандидат ПР№2 (ADR-002) |

## 1. Формулировка

«Пороги решения о скидке по сроку годности в модуле `dishbatch/decision` можно задать в файле конфигурации `discounts.conf` во внутреннем хранилище приложения. Формат — строки `ключ=значение`, ключи `writeoff`, `heavy`, `light`; значения — доли оставшегося срока жизни (0…1). Приоритет: значения из файла; при отсутствии файла или невозможности чтения — значения по умолчанию 0.05, 0.20, 0.50. При повреждённом содержимом (значение — не число; вне диапазона 0…1; нарушен порядок `writeoff` < `heavy` < `light`; заданы не все три значения) используются значения по умолчанию и выдаётся сообщение; приложение продолжает работу. Изменения файла вступают в силу после перезапуска приложения. Ни на одном пути (успех, ошибка получения, ошибка чтения, ранний выход) не должен оставаться незакрытый дескриптор файла конфигурации».

Пороги решения по темпу продаж (`VelocityDiscountDecision`) CR-001 не затрагивает.

## 2. Мотивация

Сейчас пороги — константы в `ExpiryDiscountDecision` (`app/src/main/java/com/kitchino/app/dishbatch/domain/ExpiryDiscountDecision.kt:8–10`). Изменить их можно только пересборкой приложения: сотрудник ресторана не может подобрать пороги под фактический спрос. Вынос в файл конфигурации позволяет менять поведение решения без новой сборки. Вместе с порогами фиксируются строки причин: сейчас в причинах решения жёстко записаны «Менее 5%…», «Менее 20%…», «Менее 50%…» (`ExpiryDiscountDecision.kt:26, 28, 30`) — при настраиваемых порогах причина должна строиться из фактических значений, иначе решение объявляет пороги, которых нет.

## 3. Требования к поведению при отказе

| Случай | Требуемое поведение |
|---|---|
| Файл корректен | Пороги из файла; причина решения формируется из фактических порогов |
| Файл отсутствует или нет права чтения | Значения по умолчанию; сообщение пользователю; работа продолжается |
| Повреждённое содержимое | Значения по умолчанию; сообщение; работа продолжается; ложный успех не публикуется — «решение по конфигурации» не объявляется |
| Ошибка или ранний выход в процессе чтения | Файл закрыт на всех путях; решение по значениям по умолчанию |

Таймаут и повтор не требуются: файл локальный, исход операции однозначен. Деградация — работа на значениях по умолчанию; ограниченность состояния сообщается пользователю.

## 4. Критерии приемки

1. Без файла конфигурации поведение и существующие тесты порогов не меняются (значения по умолчанию).
2. Корректный файл изменяет пороги; причина решения содержит фактические значения.
3. Отсутствующий, недоступный и повреждённый файл дают значения по умолчанию и сообщение; процесс не завершается аварийно.
4. После каждого из случаев у процесса нет незакрытого дескриптора файла конфигурации.
5. Домен `dishbatch/decision` остаётся тестируемым на JVM без Android: доступ к конфигурации — через интерфейс-источник, реализация которого подменяется в тестах.

## 5. Прогноз влияния на участок 

- Новый системный ресурс участка: файл `discounts.conf`; владелец — читающий компонент (`DiscountConfigReader`); потребители — реализации `DiscountDecisionProvider`.
- Обновлению подлежат: модульная карта (новая зависимость `dishbatch/decision` → чтение конфигурации), таблица системных границ участка (ПР№3, Р4), ADR-002 (новая редакция или ADR-004).
