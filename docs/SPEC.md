## 1. Назначение продукта

Приложение для персонала ресторана: учёт склада и рецептов, контроль срока годности готовых блюд с подсказкой «скидка или списание», фиксация, кто приготовил блюдо.

## 2. Пользователи

- **Повар** — готовит блюдо, списывает ингредиенты.
- **Кассир** — применяет скидку на блюдо с истекающим сроком.
- **Менеджер** — контролирует склад и принимает решения о списании.

## 3. Основной сценарий

Повар готовит блюдо по рецепту, далее со склада списываются ингредиенты, создаётся партия блюда со сроком годности, далее по мере приближения срока приложение показывает рекомендацию (без действия, скидка, списание), далее сотрудник применяет решение и решение сохраняется в истории, статус партии меняется.

## 4. Ошибки и особые случаи

ID - Ситуация - Ожидаемое поведение
E-01 - Не хватает ингредиента при списании - Отказ со списком недостающего, склад не меняется
E-02 - Рецепт с таким id не найден - Результат «рецепт не найден», склад не меняется 
E-03 - Срок истечения партии не позже времени изготовления - Списание с причиной, без падения 
E-04 - Срок годности партии истек - Списание
E-05 - В базе нет партий - Экран показывает «Нет партий блюд» 

## 5. Функциональные требования

Условие - действие - ожидаемый результат
ID - Требование и критерий 

Участник 1 - Скрыпникова Д.М.
FR-01 - Хватает всех ингредиентов - `WarehouseApi.consumeIngredients(recipeId, batchSize)` - `Success`; `remainingVolume` каждой задействованной партии уменьшен на `amountPerUnit * batchSize`; записи в `consumption_log` добавлены 
FR-02 - Не хватает хотя бы одного ингредиента - `consumeIngredients` - `InsufficientStock(missing)`; в `missing` для каждого дефицита: `ingredientId`, название, недостающее количество, единица; партии и журнал не изменены 
FR-03 - Рецепта с таким `recipeId` нет - `consumeIngredients` - `RecipeNotFound`; партии и журнал не изменены
FR-04 - Прогноз по ингредиенту - `ForecastUseCase.execute(id)` - `IngredientForecast` с полями: `currentStock`, `daysUntilEmpty`, `daysUntilExpiry`, `usableDays`, `shouldReorder`, `shouldUseUrgently`; для несуществующего id - `null` 
FR-05 - Расход по ингредиенту за последние 30 дней - среднее арифметическое по дневным суммам из `consumption_log`; при отсутствии истории средний расход = 0,0, `daysUntilEmpty = null`
FR-06 - Списание при нехватке в одной партии - распределяется по нескольким партиям в порядке возрастания `expirationDate`; общий списанный объём равен требуемому

Участник 2 - Стрельцова В.С.
FR-07 - Создаётся партия - сохранены блюдо, сотрудник, количество, время изготовления и истечения, статус «активна» - партия читается из БД
FR-08 - Доля остатка срока f = (истечение − сейчас) / (истечение − изготовление). f ≥ 0,5 - «без действия»; 0,2 ≤ f < 0,5 - скидка 20%; 0,05 ≤ f < 0,2 - скидка 50%; f < 0,05 - списание
FR-09 - Срок истечения ≤ времени изготовления - `recommendAction` - «списание» с причиной, исключения нет
FR-10 - Применено решение «скидка» или «списание» - запись в историю решений и статус партии «со скидкой» или «списана»; решение «без действия» статус не меняет
FR-11 - Открыт экран партий - список активных партий с данными и цветом по решению; партий нет - «Нет партий блюд» 

Участник 3 - Чемякина П.Д.
FR-12 - Правильный пароль - `EmployeeRepository.login(pin)` - найден сотрудник, сохранен как текущий, запись в журнал «вход»; неверный пароль - `null`, запись в журнал «Неверный пароль»
FR-13 - Сотрудник выполняет действие - `PermissionChecker.can(role, action)` - `true` для разрешенных пар, `false` для запрещенных
FR-14 - Действие (списание, скидка, правка рецепта) - `AuditChain.append(prev, actorId, action, payload)` - новая запись с `prevHash` = хеш предыдущей, `hash` = SHA-256 от полей
FR-15 - Сотрудник отвечает на карточку обучения - `SM2Scheduler.schedule(progress, quality)` - пересчитаны `intervalDays`, `easeFactor`, `nextReviewAt`, `repetitions`; ошибка (quality < 3) обнуляет `repetitions` и ставит интервал 1 день; `easeFactor` не ниже 1.3 
FR-16 - Журнал аудита проверяется - `AuditChain.verifyChain(logs)` - `null`, если цепочка валидна; id первой подменённой записи, если хеш или `prevHash` не совпадает
FR-17 - Открыт справочник рецептов - виден список рецептов и состав выбранного (через `WarehouseApi.listRecipes()` и `getRecipeInfo()`) 

## 6. Нефункциональные требования

NFR-02 - Устройство без сети - запуск - функции MVP работают; в манифесте нет разрешения INTERNET - Просмотр манифеста, запуск в режиме полёта

NFR-07 - Журнал записей - `verifyChain()` - время растёт линейно O(n) - Замер времени 


## 7. Зафиксированный MVP
Версия MVP закрывает основной сценарий: повар готовит блюдо - партия создаётся со сроком годности - система показывает рекомендацию - сотрудник применяет решение. Всё, что за пределами этого сценария, вынесено в резерв. 

**Обязательно для основного сценария:**

**Участник 1 (склад и рецепты):**
FR-01 — списание ингредиентов при приготовлении
FR-02 — отказ со списком недостающего, если чего-то не хватает
FR-03 — отказ, если рецепта нет
FR-05 — средний расход за 30 дней 
FR-06 — списание по партиям в порядке срока годности

**Участник 2 (партии блюд):**
FR-07 — создание партии со сроком годности
FR-08 — простое правило скидки по доле остатка срока
FR-09 — списание при истёкшем сроке
FR-10 — запись решения в историю и смена статуса партии
FR-11 — экран партий с цветом по решению

**Участник 3 (сотрудники):**
FR-12 — вход по PIN, сохранение текущего сотрудника
FR-13 — RBAC: проверка прав роль * действие (реализовано, нужны тесты)
FR-17 — справочник рецептов (согласовать с Участником 1: он даёт данные через `WarehouseApi`)

**Резерв (основной сценарий выполняется без него):** прогноз расхода продуктов; обучение с интервальным повторением; защищенный журнал действий; проверка прав по ролям;
