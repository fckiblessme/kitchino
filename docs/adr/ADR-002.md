# ADR-002. Интерфейс принятия решений о скидках и подмена реализации

| Поле | Значение |
|---|---|
| Статус | Принято |
| Дата | 18.10.2026 |
| Автор | Стрельцова В.С. |
| Характер записи | Документирующее решение по результатам практической работы №2 МДК.01.04 |

## Контекст

Модуль принятия решений о скидках (`DiscountDecisionEngine`) долгое время существовал как один объект с двумя методами: `recommendAction` (по сроку годности) и `recommendActionWithSalesVelocity` (с учётом темпа продаж). Потребитель (`DishBatchViewModel`) жёстко ссылался на конкретный объект. Такое устройство не позволяет:

- подменять реализацию без изменения потребителя;
- тестировать потребителя с упрощённой реализацией;
- сравнивать поведение разных алгоритмов за одной границей.

## Варианты

**Вариант 1. Оставить объект-фасад.** Два метода в одном `object`. Минусы: потребитель зависит от конкретного объекта; подмена реализации требует правки кода потребителя.

**Вариант 2. Интерфейс-контракт + две реализации.** Выделить публичный контракт `DiscountDecisionProvider` с операцией `recommendAction`, реализовать базовую (`ExpiryDiscountDecision`) и расширенную (`VelocityDiscountDecision`) версии, перевести потребителя на зависимость от интерфейса, а выбор реализации вынести в точку сборки (`MainActivity` / фабрика ViewModel).

## Решение

Принят вариант 2: интерфейс-контракт и две взаимозаменяемые реализации.

- `DiscountDecisionProvider` — контракт: `recommendAction(DishBatchEntity, Long): DiscountDecision`.
- `ExpiryDiscountDecision` — решение по доле остатка срока (FR-08).
- `VelocityDiscountDecision` — базовая логика + усиление скидки, если по текущему темпу партия не успевает продаться; скорость передаётся через конструктор.
- `DishBatchViewModel` и `DishBatchViewModelFactory` принимают `DiscountDecisionProvider`.
- `MainActivity` — точка сборки: выбирает, какую реализацию передать в приложение.
- Объект `DiscountDecisionEngine` сохранён как фасад для обратной совместимости и делегирует в реализации.

## Цена решения

- Добавлены два класса (`ExpiryDiscountDecision`, `VelocityDiscountDecision`) и интерфейс; фасад `DiscountDecisionEngine` сохранён, но его роль сведена к делегированию.
- Точка сборки находится в UI-слое (`MainActivity`), что для учебного проекта приемлемо; при росте проекта точку сборки стоит вынести в DI-контейнер.

## Способ проверки

- Модульные тесты обеих реализаций: `DiscountDecisionEngineTest` и `DiscountDecisionVelocityTest` — проходят на JVM (`./gradlew test`).
- Подмена: «один потребитель, две реализации» — подключение `ExpiryDiscountDecision` и `VelocityDiscountDecision` в точке сборки не требует изменений в `DishBatchViewModel`.
